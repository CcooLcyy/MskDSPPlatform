# 远程设备接入与 SSH 隧道

## 已确认目标和范围

用户于 2026-10-20 确认实施：现场允许主动连接平台；上、下位机共同使用平台现有 gRPC 入口。上位机登录后选择设备，复用现有模块界面远程操作，并可在上位机打开 SSH 终端。保留现场直连。用户随后明确授权在既有 Ubuntu x64 服务器的独立目录及临时容器中编译下位机、执行新增测试；不部署程序、不重启或改动既有服务，不操作真机。

平台负责身份、设备归属、授权及字节转发；下位机仍执行现有模块 RPC。普通 gRPC 与 SSH 共用受限隧道基础，控制、心跳及每条数据隧道分别使用独立 RPC 流。复用平台地址/端口，不承诺客户端底层始终只有一个 TCP 连接。

## 三端结构

1. 平台：增加设备管理、设备独立令牌、按用户及设备授权（allow_grpc/allow_ssh）、在线控制连接、一次性隧道配对与有界双向转发。管理端使用现有管理员登录；普通账号只能列出自己的授权设备。SQLite 持久化设备、令牌摘要及授权，令牌仅创建/轮换时返回一次。现有账号及 AgentService 保持兼容。
2. 下位机：独立平台连接组件，由主进程管理生命周期。出厂前由上位机现场直连配置接入开关、设备身份和 SSH 设置，持久化到 `./conf/platform_access.json`；无保存配置时默认禁用。平台固定为 `60.208.15.90:50000`，地址不从文件或环境变量覆盖。重启、断电恢复和升级后自动恢复已保存接入；业务模块配置仍由 ConfigPusher 管理。主动连接平台，在控制流上接收打开隧道通知，再连接本机目标并主动建立数据流。
3. 上位机：复用现有平台登录，增加授权设备列表及平台连接模式。ConnectionManager 按逻辑服务创建本地环回适配连接，manager_channel/module_channel 复用已有业务客户端。模块发现返回的现场地址在远程模式下不用于直接网络拨号。直连/远程切换清理旧连接和过期请求，概览页恢复地址不覆盖远程模式。SSH 使用独立隧道，先验证本地环回端口，再集成现成终端组件及 russh，支持交互、窗口大小变化、退出及关闭。

## 契约与认证

规范协议为 MskDSPPlatformProto/platform/v1/remote.proto，命名空间 mskdsp.platform.remote.v1。平台由 platform-proto 子模块生成；上下位机使用固定版本镜像，交付时核对字节一致性，不能另行改变字段语义。出厂配置另外在设备 protobuf 子模块的 ModuleManage 服务追加两个管理 RPC，上下位机固定到同一版本；既有业务 RPC 保持兼容。

- DeviceAccessService.ConnectDevice：Bearer 设备令牌，首帧 Hello(device_id, agent_version, services)。令牌摘要绑定设备，不允许第二台以同身份抢占活跃连接。Welcome 返回控制连接 ID、心跳间隔。
- RemoteAccessService.ListDevices：Bearer 现有上位机访问会话；返回授权设备、在线状态、权限、服务名称和版本，不返回地址或设备凭据。
- RemoteAccessService.OpenTunnel：Bearer 用户会话，首帧指定 device_id/service；平台授权后生成隧道 ID 与一次性随机票据，经设备控制流发送 TunnelRequest。
- DeviceAccessService.AttachTunnel：Bearer 设备令牌，首帧带隧道 ID/票据；必须匹配设备及当前控制连接。下位机必须先连接本机服务，再 Attach。连接失败用控制流 TunnelFailure，平台立即向上位机返回可理解错误。
- 双向数据：配对成功后平台向两端返回 ready，随后传 data/half_close/close。每帧最多 64 KiB，不允许空 data；半关闭只关闭本方向写端，另一方向可继续返回数据。收到 EOF 不可悄悄丢弃另一方向尾部。

## 目标发现与权限边界

目标为 ModuleManager、模块名或 ssh。下位机只允许配置白名单内的模块，通过本机 ModuleManager.GetRunningModuleInfo 发现对应服务；拒绝任意 URL、路径、IP、端口和未公布名称。模块服务只能连接本机环回（将已知监听端口映射到环回，不跟随远端 IP），管理端和 SSH 使用本机配置目标。SSH 未启用时不公布 ssh。

第一版授权为设备及服务类别，allow_grpc 表示允许该设备已开放模块的全部业务操作，不能宣传为只读权限。远程 gRPC 继续使用既有业务协议，平台不解析业务载荷。后续细粒度操作授权应放到业务服务或明确引入解析层。SSH 认证和主机身份校验端到端发生在上位机与下位机；平台不保存 SSH 密码/私钥，不记录终端正文。主机密钥信任以设备身份固定，不能依赖每次变化的本地隧道端口。

## 生命周期、资源与日志

- 首帧 10 秒超时；心跳默认 30 秒、90 秒无有效心跳关闭；票据 15 秒有效且仅可消费一次；单设备最多 16 条隧道。随机令牌至少 128 位，平台数据库仅存摘要；下位机在专用 0600 文件中保存自动接入所需凭据。
- 队列必须有界（建议 8 帧 × 64 KiB/方向），单次写入/队列阻塞 30 秒超时；打开等待最多 15 秒。禁止无限制生成后台任务或缓冲数据。
- 设备断线、禁用、令牌轮换、用户退出/禁用/会话失效、权限撤销时终止相关会话。认证轮询最大延迟 1 秒。旧连接清理不能删除新连接，旧票据不能附着到重连设备。
- 断线不重放业务字节和终端输入；设备重连仅恢复在线能力，客户端重新建立访问。已有现场采集/控制任务不依赖平台在线。
- 日志使用中文，记录设备 ID、服务、隧道 ID、方向、字节数、建立/关闭原因；禁止记录设备令牌、票据、SSH 密码/私钥和原始业务字节。平台访问记录不等于 SSH 命令正文审计。
- 平台连接统一使用明文 gRPC，可连接普通主机地址，不限制为本机环回。平台与下位机均无需证书或额外的明文开关，上位机登录本平台时使用 `http://60.208.15.90:50000`。此次不修改已有登录设置页面、部署环境或服务器配置。
- 上位机平台登录和远程访问共用登录设置中的 gRPC 地址，本部署使用 `http://60.208.15.90:50000`；账号、设备令牌与访问授权检查仍然生效。明文连接不会加密传输中的账号密码、设备令牌和业务字节，SSH 内容仍由 SSH 协议端到端加密。

## 实施顺序与测试

按文档 → 失败测试 → 实现推进，用户“开始工作”已授权按上述讨论方案落地，不需重新确认每个常规实现选择。

1. 契约与组件设计：固定 RPC 字段、生命周期及错误码。
2. 平台：设备存储/摘要认证/授权的单元测试，真实 localhost tonic 的握手/重复连接/心跳、越权与离线测试；隧道双向 echo、二进制、半关闭、票据复用、超时、错误、取消与清理、授权撤销、帧及数量限制测试。
3. 下位机：本机目标解析/白名单测试；假平台与本地 echo 测试验证转发及关闭，控制线程停止与重连。Windows 本机仅运行纯配置及契约检查；用户追加授权后，已在既有 Ubuntu x64 服务器隔离容器中完整编译，并通过 CTest 2 个目标（含 GTest 7 条用例）。ARM64 与真机仍待验证。
4. 上位机：设备列表/远程模式及地址适配测试，避免概览页覆盖远程模式；隧道与 SSH 会话关闭/主机身份测试；前端类型检查、构建、lint 和相关既有测试。
5. 联合验证：本地使用假设备控制连接和 echo/模拟 gRPC，验证平台与上位机契约。完整现场控制、真实 SSH、网络抖动及 ARM64 真机验证需要另行确认远端范围，不能以本地测试宣称通过。

## 最终验收

- 平台管理员能创建设备、配置账号权限、禁用或轮换凭据；上位机能看到授权设备及可信在线状态。
- 下位机从现场主动上线，平台不直接拨入现场。
- 上位机选择设备后，现有管理及各模块 gRPC 均走隧道，持续订阅可用；不会尝试家中不可达的现场 IP。
- 上位机终端可以实际完成 SSH 登录、交互、调整窗口和退出，主机密钥发生变化时拒绝静默信任。
- 失效授权/断线不会补执行控制命令；旧连接、票据、任务与环回监听得到释放；现场任务自主运行。
- 如受本机环境限制尚未完成三端编译/联调，必须列明已实现、已验证、未验证项，不宣称已达到现场验收。

## 启用步骤（待获授权后部署）

1. 确认上下位机可访问固定平台 `60.208.15.90:50000` 的明文 gRPC 入口；上位机登录使用 `http://60.208.15.90:50000`，下位机出厂配置卡只读显示地址，无需证书或传输开关。
2. 平台管理员在 `/accounts` 创建上位机账号，在 `/devices` 创建设备，保存只显示一次的设备令牌，再给账号配置模块访问和 SSH 权限。
3. 设备出厂前，上位机通过现场下位机的管理地址直连，在“平台接入配置”中填写设备 ID、设备令牌、接入开关，以及需要的 SSH 开关和该机实际 SSH 端口。页面固定显示平台地址，没有地址编辑项；离线工作区和平台远程模式不开放此配置入口。
4. 保存后下位机先原子持久化，再立即切换连接任务。空令牌输入保留已有凭据；读取只返回是否已配置，不回显明文。成功保存不代表平台已经在线，网络暂不可达时后台自动重试。
5. 持久文件为 `./conf/platform_access.json`，权限 0600，位于已有宿主机 conf 持久挂载。重新上电、进程重启和安装器更新/同版本重建后自动读取，无需环境变量。损坏文件会报告错误并保持接入关闭，不影响现场业务模块运行。
6. 如启用 SSH，确认平台连接组件所在网络命名空间能够通过本机环回访问管理服务与 SSH 服务。容器部署仍需正确的本机服务布局；此要求与凭据持久化分开处理。
7. 在家中上位机登录固定平台，选择已授权在线设备；管理和各模块操作走隧道。点击“SSH 终端”后以现场系统账号密码登录，首次连接核对设备主机指纹。先验收只读管理及实时订阅，再验证配置与控制；现场直连可显式恢复。

出厂配置复用 `ModuleManagerProto.ModuleManage.GetPlatformAccessConfig` 与 `SetPlatformAccessConfig`，不新增监听端口。字段、修订冲突及原子保存契约以 `MskDSP/doc/平台接入出厂配置方案.md` 为准。

本轮新增终端支持密码认证；现有高级配置的独立 SSH 升级流程不自动切换到平台隧道。不能用终端测试通过替代模块控制及升级功能的逐项验收。

## Ubuntu 试用配置示例

以下是供试用时自行填写的新配置示例，不会自动更改现有服务器。平台 gRPC 使用明文并监听可达网卡：

```toml
# config.trial.toml
[server]
http_addr = "0.0.0.0:8080"
grpc_addr = "0.0.0.0:50000"

```

平台继续使用已有配置文件启动。出厂配置由上位机现场直连下发，不需要在下位机启动命令或容器环境中设置设备身份和令牌。

上位机登录本平台使用 `http://60.208.15.90:50000`；这是 gRPC 端口，不是 Web 管理端口。出厂保存后，可重启下位机并在平台设备列表确认重新上线，再进行远程模块与 SSH 验收。安装器会保留宿主机 conf 并继续绑定到容器 `/opt/mskdsp/conf`。
