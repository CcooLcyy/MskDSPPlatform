# 平台自身 CI 包入库与自动更新

## 已确认目标与范围

GitLab 完成构建、测试和打包后只向平台上传程序更新包；平台保存历史版本，由 Python 管理进程在平台就绪后每 60 秒检查一次，发现新版本自动安装。CI 上传动作本身不发布、不安装、不重启；安装由独立的定时任务或管理员手动动作发起。此次只实现 CI、Linux amd64；上下位机软件发布语义保持兼容。

## 数据及接口契约

复用 SoftwarePublishService 的 CreateUpload → GetUpload/UploadPackage → CompleteUpload，不调用 PublishRelease。产品为 mskdsp-platform，架构为 linux-amd64，channel 为 ci，版本沿用现有 0.0.1-ci.<UTC时间>.<流水线>.<作业>+sha.<短SHA> 规则；source_ref 为 main，source_sha 为完整小写 SHA，build_time 为带时区的构建时间。

PackageMetadata 在现有字段之后兼容增加 build_time=14、channel=15；Rust JSON 字段缺省为空，保留旧包读取兼容。程序包使用现有单根 mskdsp-platform 文件的 binary.tar.gz，size/sha256 为压缩包大小和摘要。上传完整性确认后保存到 software/packages/mskdsp-platform/<版本>/linux-amd64/<文件名>，SQLite 保存元数据；不能将平台包发布到上下位机公共更新目录。

软件配置增加 ci_upload_token_sha256；CI 专用令牌仅允许上述四个上传 RPC，且只能操作平台自身 CI 包，不能发布、撤回或操作上下位机包。管理员发布令牌保留旧权限。令牌原文仅存受保护的 GitLab CI 变量，平台只保存摘要，不输出到日志或命令参数。

## 平台检查及安装

Python 常驻管理进程新增平台本地软件仓库来源，updater.json 为 {"source":"platform","channel":"ci"}。由同一个持久化业务根目录定位 software/software.sqlite3，以只读方式读取完成入库的平台 CI 包并按现有版本顺序选择最新候选，不依赖自身 HTTP 服务、公开下载 URL 或 R2。

自动任务首次等待 60 秒，每轮复用既有检查与安装流程；没有包或没有更新时不切换程序。有检查、安装或回退任务正在运行时跳过本轮，退出时停止调度。无有效更新源时不运行自动任务；检查或安装失败保留诊断，下一轮继续检查重试。

管理员点击检查仍仅比较身份和版本；没有包时显示暂无可升级版本。自动安装或点击升级后，先将选定包复制到独立临时目录、核对大小/摘要、解包及校验 ELF/构建身份，再停止旧平台子进程。新进程通过 HTTP/gRPC 健康检查后提交安装状态；失败恢复上一版本。保留现有远端来源兼容测试，新的默认 CI 运行和部署配置不再指向 R2。

`GET /api/update/status` 以 `auto_update_interval_seconds` 声明自动策略：有效更新源为 60，无源为 0。新页面读取该字段后显示自动安装策略；旧管理器没有该字段时继续显示手动更新，页面本身不定时提交检查或安装请求。

不在软件仓库入库动作中运行包内程序。运行版本、候选包和安装状态相互分离；数据库变更须兼容此次升级前后的软件仓库和点表数据，程序回滚不能替代数据库备份。

## 管理员手动回滚

平台继续采用现有 CI 单通道滚动更新。保留安装期间启动失败自动恢复旧版本；平台仍可访问时的业务问题由管理员判断，不增加运行期间的自动回滚或观察期。自动安装按上述每 60 秒策略执行；手动回退后若仓库仍有更新版本，下次检查会再次自动安装，本次不提供暂停自动更新功能。

`GET /api/update/status` 增加 `previous_version`（无记录时为空字符串）和 `rollback_available`。上一版本记录与本地程序存在时允许回滚；回滚不依赖更新源或软件仓库。页面显示目标版本，管理员确认后提交 `POST /api/update/rollback`，JSON 为 `{"target_version":"状态接口返回的上一版本"}`。该接口沿用管理员 Cookie 会话、同源检查、`X-MskDSP-Action: update`、请求体上限及提交前再次验证会话。目标缺失、已变更或任务冲突返回 409，参数无效返回 400，成功受理返回 202。

回滚与检查、安装共用任务互斥和文件锁，任务状态新增 `rolling_back`。停止当前平台进程前重新验证上一版本的路径、ELF、构建身份及已记录的可执行文件 SHA256；种子程序按保存身份核对。新升级为当前和上一版本分别记录 `executable_sha256`，原 `binary_sha256` 继续表示安装包归档摘要；兼容旧安装状态缺少新字段的情况，仍检查本地文件、ELF 与身份。校验失败不停止当前进程。回滚目标通过 HTTP 就绪、版本身份及 gRPC 握手检查后，原子保存安装状态；目标启动或状态提交失败时恢复回滚前的程序，恢复失败明确报告人工处理。提交成功后即使任务结果保存失败，也不撤销已提交版本。

回滚成功使用 `rolled_back` 状态，清除旧的检查结果与上一版本指针，不将刚撤下的版本作为新的回滚目标；重启继续使用已回滚的版本。页面不自动提交回滚，任务期间禁用操作；回滚完成后可重新登录并检查更新。当前及上一版本之外的程序目录沿用既有清理规则。日志记录回滚受理、来源和目标版本、成功或失败；回滚不恢复数据库，也不改变 GitLab 的上传行为。

验收覆盖无上一版、缺文件/链接/身份/摘要异常、过期目标、并发任务、认证与跨源拒绝、无更新源仍可回滚、成功持久化、目标启动失败恢复当前版、恢复失败提示、中断恢复，以及页面确认取消、重复点击、断线和任务完成行为。

首次启用必须更新基础镜像中的 Python 管理器，并安装包含新页面的平台程序；仅通过现有 gRPC 安装 Rust 程序包不会更新管理器、启用自动更新或新增回滚接口。旧管理器返回的状态没有回滚能力字段时，新页面保持回滚按钮禁用。更换管理器或基础镜像须保留既有工作目录、数据库、配置和安装状态，并核对种子身份；本次源码实现不代表已完成线上管理器更新。

## GitLab 与部署顺序

打包产物改为与下载域名无关的程序包和元数据；CI 最后一步为 upload-platform，使用固定协议生成客户端、按偏移续传、完整性校验后查询完成状态，失败保留 GitLab 产物。清除 CI 的 R2 发布任务与依赖；首次部署用离线镜像或已验证本地镜像引导接包服务，再启用平台上传任务。

现有 Runner 和平台同宿主机，优先使用受控的宿主机/Docker 内网入口上传，避免向公网明文 gRPC 发送令牌；公网提供给外部发布端时使用 TLS。bootstrap 时备份平台工作目录和部署配置，保留现有端口及挂载，只调整平台相关容器；不操作其他业务服务。

首次引导必须显式迁移安装状态：仅替换镜像仍可能继续运行持久化的旧程序；旧状态为 seed 时还会触发种子身份不一致。备份旧 state.json 后以新镜像种子身份建立当前状态，保留上一版身份和程序以便恢复。若回退到尚不支持平台包元数据的历史程序，同时恢复引导前的软件库备份；后续程序回滚不承诺自动回滚数据库。

## 验收

先补失败测试再实现：平台元数据和只上传权限、幂等/续传/摘要错误、平台包不能公开发布、最新版本选择、旧包晚到、防路径穿越、检查不安装、复制后切换、失败回滚，以及干净协议检出构建。新增调度验收覆盖首轮等待与每 60 秒检查、有更新自动安装、无更新不切换、忙时跳过、失败恢复后继续检查、无源禁用和退出停止，以及新旧管理器页面策略兼容。完成 Rust/Python/页面相关检查，统一通过对应提交的 CI 执行。

线上验证固定提交的流水线成功入库，包摘要与来源一致；核对入库后由定时任务在下一轮自动升级到候选版本，而非上传动作直接安装。另验证管理员手动检查与安装仍可使用，核对 HTTP/gRPC、配置及数据；使用隔离临时运行目录验证失败回滚，不破坏线上正式包。最后核对日常更新不访问 R2，记录源码验证和现场验证的区别。
