# Modbus 点表管理

## 目标与边界

平台提供 `/modbus-templates` 点表库界面，支持导入上位机导出的 JSON 模板、新建、查看、逐点编辑、增删点位、保存、下载和删除。首页提供点表库入口，保留程序更新入口。本次增加平台 SQLite 持久化并同步放宽上位机模板校验，不新增上位机联机同步或设备下发功能。

使用 `MskDSPUpper/src/features/modbus-templates/model.ts` 的 `schema_version=1` 格式，RTU/TCP 共用；真实功能码为 1、3、4、5、6、16。工程量参数 scale/offset/deadband 保留十进制字符串。文件最大 10 MiB、每表 1 至 10000 点，字段与组合校验对齐同步放宽后的上位机。下载的 JSON 可通过上位机的“导入模板”使用；旧上位机仍限制 2 MiB / 2000 点，超过时须先升级上位机。网页未保存改动需提示，服务端返回中文校验错误。

上位机拒绝与内置模板或已有个人模板重复的模板 ID。平台保留上传文件的 ID；需要导入修改后的副本时，可使用“复制为新点表”，或修改模板 ID 后保存、下载。格式化下载也必须不超过 10 MiB。

## 接口与持久化

- `GET /api/v1/modbus-templates`：返回摘要数组，含平台 id、revision、name、manufacturer、models、protocol_version、address_base、point_count、created_at、updated_at。
- `POST /api/v1/modbus-templates`：请求体为模板对象，创建后返回 201 和完整记录。平台分配 UUID，模板自身 id 保留；不会按名称或模板 id 自动覆盖现有记录。
- `GET /api/v1/modbus-templates/{id}`：返回完整记录 `{id, revision, created_at, updated_at, template}`。
- `PUT /api/v1/modbus-templates/{id}`：模板对象替换，必须携带 `If-Match: <revision>`，成功返回完整记录；旧版本返回 409，缺少版本返回 428。
- `DELETE /api/v1/modbus-templates/{id}`：必须携带 `If-Match`，成功返回 204，将完整记录移入回收站保留 90 天。
- `GET /api/v1/modbus-templates/{id}/download`：仅输出模板 JSON，下载文件名使用模板自身 id。
- `GET /api/v1/modbus-templates/trash`：返回未过期回收站摘要，包含原平台 id、删除后的 revision、deleted_at、expires_at 及点表摘要。
- `POST /api/v1/modbus-templates/trash/{id}/restore`：必须携带 `If-Match` 及点表操作标记，恢复原 id 和完整模板，递增 revision，成功返回完整记录；过期或不存在返回 404，旧 revision 返回 409，正常库已满按容量错误返回，不覆盖其他记录。

页面及全部点表接口接入平台现有管理员登录认证，未登录的页面访问跳转 `/login`，接口返回 401。写接口还需 `X-MskDSP-Action: modbus-template` 标记及同源请求；标记用于防跨源误操作，不能替代登录认证。

数据根目录按非空 `MSKDSP_PLATFORM_DATA_DIR`、`MSKDSP_RUNTIME_DIR/data`、当前工作目录下 `data` 的顺序选择；点表保存在其 `modbus-templates/templates.sqlite3` SQLite 数据库。容器目录 `/var/lib/mskdsp-platform/data` 映射宿主机 `/home/daniel/mskplt/runtime/data`，兼容旧镜像缺少数据目录环境变量的网页更新。数据库随程序内置，无需部署独立数据库服务。

数据库保存平台 UUID、revision、创建/修改时间、名称、厂家、型号等摘要字段及完整模板 JSON；工程量十进制字符串保持原样。列表直接查询摘要字段并按修改时间排序，不读取和校验全部模板正文。新增的容量检查、修改/删除的 revision 检查与实际写入在同一事务中执行；独立存储实例也不能突破容量或覆盖旧版本。存储错误不报告成功，也不自动丢弃损坏记录。时间戳为 Unix 毫秒。revision 是当前记录的并发控制版本号，本期不保存每次修改的历史版本。

### 误删恢复与回收站

删除只将记录从正常库移入 SQLite 回收站，不立即丢弃模板。保留完整模板、原 id、创建时间以及删除时间，删除与恢复各递增一次 revision；删除后正常列表、详情和下载均不可见，不能通过旧编辑草稿继续保存。恢复后内容和精确十进制字符串保持一致，更新时间更新为恢复时间。

保留期从服务端删除时间起按 90 × 24 小时计算。到期记录不可再恢复；平台子进程启动及访问回收站时检查过期记录，后台每小时清理过期数据。中断、重启或程序更新不重置保留期。页面提供回收站入口、删除/到期时间、恢复按钮，并明确删除后 90 天内可恢复。本期不提供手动永久删除或清空回收站功能。

正常库最多 1000 张，回收站不占正常库名额。恢复时仍须在事务内检查正常库容量；容量不足或版本冲突时，回收站记录保持不变。回收站仍占磁盘空间，按 90 天保留窗口积累，不承诺固定空间上限。

数据库结构从 v1 事务迁移至 v2，升级不改动现有正常点表的 id、内容、版本和时间。旧程序不支持 v2，拒绝加载以避免永久删除绕过回收站；不能仅回滚到旧可执行文件。部署前使用 SQLite 一致性备份，失败回退必须同时恢复对应数据库与原程序状态；备份不使用点表 JSON 文件。

### 数量与大小限制

| 项目 | 当前限制 | 原因 |
| --- | --- | --- |
| 点表总数 | 最多 1000 张 | 平台业务容量；达到上限仍可编辑、删除已有点表 |
| 每张点表点位数 | 1～10000 个 | 与同步更新后的上位机模板及网页校验一致 |
| 模板 JSON | 最多 10 MiB（10,485,760 字节） | 创建/修改请求及格式化下载均受限制 |

上述是平台的业务限制，不是 SQLite 只能保存 1000 条。1000 张点表理论上最多包含 10,000,000 个点，但每张仍须满足 JSON 字节限制；这不是已经验证的满容量性能承诺。数据库、索引、迁移备份及事务文件另占磁盘，不能把 1000 × 10 MiB 当成完整工作目录的空间上限。本期列表仍一次返回摘要，后续继续扩容需结合分页、备份及负载验证。

管理进程代理同步放宽至 10 MiB，其他业务请求保留原上限。网页更新仅替换 Rust 程序，旧镜像中的 Python 管理器仍限制 2 MiB；要使用超过 2 MiB 的请求，需要以新镜像重建平台容器并保留工作目录挂载。无需启动额外数据库容器。

### 旧 JSON 迁移与回滚

平台子进程启动时自动将旧 `modbus-templates/*.json` 记录一次性导入数据库，保留 UUID、revision、创建/修改时间和完整模板。所有旧记录通过校验后在同一事务提交；遇到损坏、超限或不兼容数据时拒绝启动平台子进程并保留原始数据，不部分导入。迁移事务同时暂存原始字节作为清理恢复依据，提交后才逐条核对并删除旧 JSON。清理中断时，下次初始化继续恢复；成功后删除恢复快照，数据库成为唯一业务数据源，不保留旧 JSON 文件或 `legacy-json` 备份目录，不复活已删除记录。

数据目录保留空的 `database-required.json` 保护目录，利用旧程序的文件名检查令其拒绝列出或新增点表，避免回滚旧程序后误创建空库。该目录不是 JSON 文件，不含业务数据；此前版本的 JSON 标记文件会自动转为保护目录。迁移后的业务操作需要支持数据库的程序；不能仅回滚可执行文件就恢复到 JSON 存储。确需恢复旧程序，应先停止平台，完整备份当前数据目录，再使用迁移前的外部备份恢复；迁移后新增/修改的数据须另外导出处理。不要手工删除兼容保护目录或数据库。

备份时先停止平台子进程，再复制整个 `modbus-templates` 目录，包含数据库、可能存在的 SQLite 事务文件和兼容保护目录。程序版本清理只作用于 `runtime/releases`，不会删除此业务目录。JSON 只用于模板导入导出，不作为服务端业务文件保存；更新器的 `state.json`、`task.json` 是独立运行状态，不属于点表存储清理范围。

## 验收与异常场景

1. 上位机内置及个人模板导入后，字段完整，下载再通过上位机校验；科学计数法与精确十进制字符串不丢失。
2. 网页新建、修改点位及可选条件/枚举字段，保存后重新读取一致；失败时保留编辑内容。
3. 空表、重复标签/点位 id、越界地址、错误功能码/类型/寄存器组合、非法十进制、未知字段与未知版本被拒绝。
4. 服务重建存储实例后记录仍存在；并发旧版本覆盖/删除被拒绝；不存在记录返回 404；非法平台 id 不允许路径穿越。
5. HTTP 请求限 10 MiB，管理进程点表请求同步支持此限制；已有更新请求限制保持原值。
6. 页面状态和内容使用文本或表单赋值，导入内容不得作为 HTML 执行；请求期间禁用重复操作，错误以中文展示。
7. 真实 SQLite 文件保存摘要和完整记录；数据库重开后数据及精度不变，跨实例并发创建不能超过 1000 张，并发更新仅一个旧 revision 请求成功；10000 点通过，10001 点拒绝。
8. 旧 JSON 迁移原子且可重试，损坏记录不产生部分数据；删除后重启不重新导入，迁移成功后清理原 JSON、旧备份和恢复快照，旧程序兼容保护目录保留。
9. 删除后正常接口返回 404，回收站保留完整记录且重启后仍可恢复；恢复保持原 id、创建时间与完整模板，revision 递增，旧保存/删除请求不能覆盖恢复后的记录。
10. 90 天期限前可恢复，到期边界及之后不可恢复；过期清理不删除正常记录或仍在期限内的回收站记录。恢复并发、容量不足、错误版本和存储失败不丢弃回收站内容。
11. 回收站及恢复接口均要求管理员认证；缺少操作标记、跨源请求及缺少 If-Match 被拒绝。页面覆盖移入回收站、恢复、空回收站、恢复失败提示及过期时间显示。

按文档先补校验、持久化、HTTP 合约与页面交互测试，再实现并完成本地构建与相关回归。发布与远端部署不在本次验收范围内。
