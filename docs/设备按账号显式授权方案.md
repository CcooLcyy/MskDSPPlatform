# 设备按账号显式授权

## 已确认需求与范围

2026-10-23 用户确认实施：账号管理页面“上位机角色”为管理员（`admin`）的有效账号自动拥有全部下位机访问权限，包括后续新增设备；运维人员（`operator`）默认不可见，只有平台 Web 管理员明确分配后才能查看和操作对应设备。用户名不参与管理员判断，上位机管理员仍不获得平台 Web 管理身份。

本次修改平台远程设备列表、隧道访问及管理页面说明，不改变现场直连鉴权、不修改业务 RPC 或协议字段、不部署服务器或操作现场设备。设备禁用、会话过期、账号禁用、设备服务白名单和 SSH 系统账号认证继续生效；管理员全权限不代表可以访问已禁用设备或绕过设备 SSH 认证。

## 授权规则与接口

- 普通账号的 `ListDevices` 仅返回明确授权且设备已启用的记录，未授权设备的名称、编号、状态、服务、版本均不返回；知道设备编号仍无法建立隧道。
- 管理员的 `ListDevices` 返回全部已启用设备，`allow_grpc`、`allow_ssh` 均为 true；离线设备可见但不能建立连接。每个设备实际公布的服务仍决定可连接服务。
- `OpenTunnel` 在建立前和建立完成后检查有效会话及最新账号角色。管理员自动通过账号授权检查，普通账号按设备及服务类别检查明确授权。
- 既有隧道继续按一秒周期读取当前会话和账号角色。管理员降级时，未明确授权的连接终止；仍有明确授权的连接保留。普通账号撤权后相应连接终止，已交付设备执行的操作不自动回滚。
- 新建设备不为任何账号自动创建授权；创建新账号也不补授现有设备。管理员通过角色立即覆盖新设备，无须写入每个设备的授权行。
- 保留普通账号 `allow_grpc`（模块访问，包含配置与控制）、`allow_ssh` 两项已有授权类别。管理员在设备权限页面显示“全部权限”，不提供可产生误解的手工取消选项；普通账号继续勾选并保存。
- 授权管理沿用平台 Web 管理员认证、来源校验及现有 PUT 接口，客户端传入的角色不能影响服务端鉴权。服务不可用时拒绝访问，不沿用过时角色放行。

## 旧数据升级

旧版设备数据库版本为 1，授权记录没有自动分配与手工分配的来源信息。无法可靠区分这些记录，因此迁移至版本 2 时保留所有旧记录并将其标记为未确认；旧记录不参与有效权限查询，管理页面也不将其显示为有效授权。管理员不受影响，普通账号需由 Web 管理员重新保存设备授权。

`grants` 增加 `confirmed` 标记；新库直接使用版本 2。明确创建或保存的授权写入 `confirmed=1`。迁移在单个事务中检查旧表结构、增加字段并更新版本，失败不得留下部分升级。迁移只执行一次，重新打开版本 2 数据库不能再次撤销已确认授权。日志记录旧记录待确认数量，不记录凭据。

## 验收标准

1. 无授权的普通账号设备列表为空，直接请求已知编号的模块或 SSH 隧道被拒绝。
2. 分配 A 后只能看 A，访问类别符合勾选值；B 的信息不可见。
3. 管理员不依赖 grant 行，可看并连接全部已启用设备及后续新增设备；用户名为 admin 的普通角色不获得特权。
4. 管理员升降级对已有会话生效，不要求重新登录，不延长会话；降级后未授权隧道关闭，有授权隧道继续。
5. 创建新设备保持授权为空，管理员照常可见；无账号时创建行为一致。
6. 版本 1 旧授权暂停生效但记录保留；重新保存后恢复明确授权，重开数据库后仍有效；损坏旧库升级失败且不部分修改。
7. 管理界面清楚说明默认不授权、管理员自动拥有全部设备及历史授权需重新确认，不提交管理员自动权限为普通账号授权。

先补行为失败测试，再实现；运行真实 localhost gRPC、SQLite 迁移、HTTP API 与页面 JavaScript 测试以及格式检查。本地验证不能替代已部署平台与现场设备验收。

## 首帧撤权回归的 CI 稳定性（2026-10-23）

GitLab 流水线 139 的 Rust 回归在发送首帧时收到 `SendError`，尚未进入权限结果断言。测试在服务开始等待首帧后才执行 SQLite 撤权操作，受真实 10 秒首帧期限约束；由源码推断，CI 负载或存储延迟可能导致请求提前超时。现有日志没有记录该请求最终的 gRPC 状态，不能将超时当作已经观测到的结果。

本次只隔离测试中的首帧等待：撤权用例通过 `cfg(test)` 入口跳过该请求的首帧期限，由外层 30 秒预算同时约束撤权操作、首帧发送及响应。发送失败必须输出请求的实际 gRPC 状态。生产首帧仍为 10 秒，其他请求及原有权限断言保持不变。

验收覆盖在线/离线设备下的降级、退出、停用六种组合，继续要求 `PermissionDenied`、无已建立隧道且未通知设备；另用 Tokio 虚拟时钟验证默认入口 10 秒后返回 `DeadlineExceeded`。执行定向 Rust 测试、完整 Rust 回归、格式及差异检查；本地验证不等同于新一轮 CI 或部署验收。

本机 Windows 验证：远程 gRPC 定向测试 19 项全部通过（17.77 秒），完整 Rust 回归 194 项全部通过（38.30 秒）；`cargo check --locked`、`cargo fmt --all -- --check` 和 `git diff --check` 通过。撤权测试在真实 SQLite 操作前用虚拟时钟跨过 11 秒，确认测试专用等待仍然有效，再恢复真实时钟完成撤权；默认首帧期限另以虚拟时钟验证 9 秒仍等待、10 秒超时。本记录未包含新的 GitLab 流水线或部署验证。

同款 Linux CI 镜像 `mskdsp-platform-ci-verify:rust1.94.1-v2` 中，`cargo fmt --all -- --check` 与 `cargo test --locked --offline --all-targets remote::grpc_tests -- --nocapture` 通过，远程访问测试 19/19。使用独立源码快照及现有 Cargo 缓存，未触发新流水线、上传产物或部署业务服务。
