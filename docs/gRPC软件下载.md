# 软件目录与流式下载安装包

## 目标与边界

上位机通过 `SoftwareCatalogService.ListPackages/GetPackage` 查询上下位机版本，并用同一平台 gRPC 连接下载安装包。保留既有 HTTP 清单、Range 下载与软件管理页面；本次不变更发布权限、通道、数据库或安装行为。

新增 `DownloadPackage(DownloadPackageRequest) returns (stream DownloadPackageChunk)`。请求字段为 `package_id=1`、`offset=2`；响应字段为 `offset=1`、`data=2`、`total_size=3`、`sha256=4`、`eof=5`。字段号与具体类型以独立协议仓库 `platform/v1/software.proto` 为准。

## 下载契约

- 公共目录与下载均不要求发布令牌。仅已发布或曾发布的上下位机包可读；未发布包和平台自身私有候选返回 `NOT_FOUND`。撤回只移除通道引用，历史包仍可按 ID 下载。
- `offset` 为已经保存的安装包字节数；各块从该偏移连续发送，单块 `data` 不超过 256 KiB。每块携带相同的完整安装包 `total_size` 和 `sha256`。
- 仅末块 `eof=true`；有数据时末块可同时含数据。`offset == total_size` 时返回一个数据为空、`eof=true` 的块。`offset > total_size` 返回 `OUT_OF_RANGE`。
- 客户端必须检查所有块的身份、偏移及末块，断线后用实际落盘偏移续传。收到 EOF 后仍须核对完整本地文件的大小/SHA256；上位机还须使用原公钥验证 Tauri 签名，下位机安装沿用现有安装包校验。流正常关闭但没有 EOF 不代表成功。

## 服务端实现

复用 `SoftwareStore.download_file` 的公开边界、文件名、链接和长度检查。打开普通文件后，在同一文件句柄上用 256 KiB 缓冲预校验完整 SHA256，再 seek 到请求偏移，避免已存在的同长度损坏包被作为成功下载发送。完整性不符返回 `DATA_LOSS`；安装包按入库后不可变管理，客户端的最终摘要检查继续覆盖传输期间的内容变化。

预校验和读取不持有软件仓库数据库锁。流生产者使用容量为 2 的有界队列，取消接收后终止读取；读取与发送等待最多 60 秒，整个请求（含预校验）最多 30 分钟，超时返回 `DEADLINE_EXCEEDED` 或在已取消/无法接收错误时直接结束不完整流。客户端应设置自身截止时间；本次不引入整包内存缓存或无限后台任务。

## 验收

先增加真实 Tonic 随机端口集成测试，再实现服务。覆盖多块原始字节和摘要、断点续传、文件尾空 EOF、越界偏移、未发布/私有候选不可读、已撤回历史包可读、截短与同长度篡改。补充取消与背压超时的生产者测试，并运行既有 HTTP 兼容测试。

本地 Windows 已有 Cargo/Rustc/Protoc，可直接编译与运行测试；本次不部署服务器。独立协议仓库与平台协议子模块在开发时同步工作树内容，最终由整合步骤先提交协议再固定平台引用，不能把未提交协议当成 CI 已可获取版本。
