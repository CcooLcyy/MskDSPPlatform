# 平台更新会话保持

## 目标与边界

平台更新允许连接短暂中断，但有效期内的上位机登录保持有效，上位机自动重连后继续使用原工作台和设备选择。复用现有上位机退避重连和页面定时查询，不通过保存密码或重新登录实现恢复。

本次只修改平台普通账号会话；网页管理员 Cookie 会话仍按原规则管理。已有 SSH 终端字节流不能跨平台进程重启接续，需要重新打开。结果不确定的控制命令、终端输入不自动重放。

## 数据与接口

在既有 accounts.sqlite3 中增加独立命名的 client_sessions_v1 辅助表，保存随机令牌的 SHA256 摘要、账号 ID、认证版本、签发时间和 UTC 毫秒到期时间，不保存令牌原文或密码。不因辅助表额外提升账号库版本；兼容性仅针对支持相同账号数据库版本的程序，既有账号结构迁移的回退限制另计。

Login / GetSession / Logout 和 ConnectAgent 的协议保持不变。登录在同一数据库事务中检查账号认证版本、清理过期及已撤销会话、校验全局 1024 / 单账号 16 的上限、写入会话及更新登录时间。验证每次读取持久会话和当前账号状态，不引入内存认证缓存；重新打开数据库、平台重启和更新不续期。

退出删除持久会话；删除失败返回 UNAVAILABLE，不能返回退出成功。账号禁用、改密仍由持久化认证版本使全部旧会话失效；重新启用不能恢复旧会话。数据库不可用时返回 UNAVAILABLE，不能把存储故障误报为登录失效或放行。

## 上位机恢复

上位机已有网络异常保留登录和 1～30 秒退避重连。远程设备本地适配监听保留，后续业务 TCP 连接重新打开隧道；页面定时查询继续运行。平台必须先恢复有效会话，再等待下位机自动上线，之后查询自然恢复。SSH 终端结束提示保持现有行为。

## 升级兼容

持久数据位于现有业务挂载内，无需更新 Python 管理进程或改变部署端口。旧版只有内存会话，首次从旧版升级时无法追回已经随旧进程消失的会话，仍需重新登录一次；随后支持本机制的版本之间更新、重启和故障恢复保持有效会话。

回退到尚不支持持久会话的旧程序不承诺保持登录；旧程序只使用自己的内存会话。运维不得通过恢复历史会话数据库备份来恢复已撤销令牌。本次不操作线上更新。

## 验收

- 先用独立 ClientAuth / 重新打开同一数据库复现更新后的旧令牌验证失败，再实现持久化。
- 重启后原令牌可查询会话、建立 ConnectAgent，剩余期限不增加；数据库中只有令牌摘要。
- 退出、禁用、重新启用、改密、过期在重新打开数据库后仍拒绝旧令牌；其他账号会话不受影响。
- 容量上限在重启和并发登录间仍有效；满额失败不修改 last_login_at。
- 存储故障时认证和退出明确失败，恢复数据库后未撤销令牌可继续验证。
- 真实本机 gRPC 服务替换后，使用同一个令牌重新查询和建立控制连接；与现有账号、远程访问回归一起检查。
