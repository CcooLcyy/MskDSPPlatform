# 账号删除与设备统一保存

## 目标与边界

- 账号管理增加永久删除入口，仅平台 Web 管理员可操作；上位机管理员角色不授予 Web 管理权限，平台管理员账号不在该列表中。
- 删除前提示账号身份与不可恢复后果。使用账号修订号检查并发修改，失败时保留界面数据并提示重试。
- 删除账号及其持久登录会话在账号数据库同一事务内完成，随后断开已有账号连接。旧会话不能继续访问；同名重建使用新账号 ID，不继承旧授权。
- 设备弹窗只保留一个“保存修改”入口，同时提交设备名称、启用状态及运维账号的模块访问、SSH 权限；管理员仍自动拥有全部设备权限。
- 不涉及部署、下位机配置或接入令牌变更。

## 接口与一致性

- `DELETE /api/v1/accounts/{id}`：JSON 请求携带 `revision`；沿用管理员 Cookie、同源检查和 `X-MskDSP-Action: account`。成功返回 204；账号不存在返回 404，修订冲突返回 409，存储异常不得误报成功。
- `PUT /api/v1/devices/{id}`：在现有 `display_name`、`enabled` 外增加可选 `grants` 数组。携带时完整替换设备授权，与设备信息同事务提交；任一校验或写入失败时整体回滚。
- 未携带 `grants` 的旧请求仍只修改设备信息；现有独立授权接口继续兼容。
- 页面保存前检查账号列表及角色是否变化，变化时要求重新确认权限，避免覆盖不再适用的授权。请求失败保留待保存内容，保存期间禁止重复提交和关闭弹窗。
- 禁用设备或撤销权限继续按现有机制断开连接；不记录密码、令牌等敏感信息。

## 验收

- 删除确认取消不发送请求；成功后账号从列表移除，详情及旧会话不可用；修订冲突、未认证及跨站请求不能删除。
- 账号删除后重新打开数据库仍不存在；同名重建不能复用旧会话或原账号 ID。
- 一个按钮保存三类设备设置，只发送一个写请求；名称或权限非法、数据库中途失败均不留下部分修改。
- 覆盖旧设备更新接口兼容、角色变化、保存失败与重复提交场景；运行相关 Rust 与实际页面 JavaScript 行为测试。

- 先补失败测试：旧进程删除接口返回 405，合并设备保存返回 422；页面也确认缺少删除入口和统一保存行为。
- `cargo test --locked`：187 项通过；包括账号删除中途存储失败回滚、设备授权写入失败整体回滚，以及真实本机 gRPC 隧道在账号删除后终止、旧会话失效、同名重建不能继承授权。
- 账号、设备、导航与主题的实际 JavaScript 行为测试共 36 项通过；覆盖删除确认、草稿保护、失败保留、唯一写请求及保存期间输入锁定。
- `test_account_api`：6 项真实平台进程测试通过，覆盖删除后的数据库状态、重启保持和统一保存持久化。

- 验证限本地 Windows 平台与模拟客户端，未执行服务器部署或现场联调。
