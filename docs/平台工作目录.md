# 平台工作目录与旧容器更新兼容

## 目标与目录

宿主机平台工作目录统一为 `/home/daniel/mskplt`，可通过部署变量 `MSKDSP_WORK_DIR` 指定其他绝对目录。平台产生的程序版本、更新状态、业务数据、日志与临时文件都保存在工作目录内，重建容器保留这些内容。

| 宿主机目录 | 容器目录 | 内容 |
| --- | --- | --- |
| `deploy` | `/app/config.toml`、`/app/updater.json` 只读挂载 | 平台配置与更新源；已有配置不覆盖 |
| `runtime` | `/var/lib/mskdsp-platform` | `state.json`、`task.json`、更新锁与 `releases` 程序版本 |
| `runtime/data` | `/var/lib/mskdsp-platform/data` | 点表等业务数据 |
| `runtime/logs` | `/var/lib/mskdsp-platform/logs` | 管理进程与平台子进程运行日志 |
| `runtime/tmp` | `/tmp` | 临时文件；更新下载仍在 `runtime/.download-*` |

Docker run 与 Compose 都使用宿主机工作目录挂载，部署准备目录时赋予容器 UID 10001 必要的写权限，保持容器根文件系统只读。管理日志 `manager.log` 与平台日志 `platform.log` 各按 10 MiB 轮换，分别保留 3 份历史。管理日志同时输出到 Docker 控制台，平台子进程日志直接落盘。

## 旧容器兼容

旧镜像只有 `MSKDSP_RUNTIME_DIR`，网页更新只替换 Rust 程序，无法自动增加新镜像环境变量。程序数据根目录依次使用非空的 `MSKDSP_PLATFORM_DATA_DIR`、`MSKDSP_RUNTIME_DIR/data`、当前工作目录下 `data`，并记录最终绝对存储路径。这样旧容器会写入已有可写挂载，而不会尝试创建只读的 `/app/data`。

## 验收与现场操作

- 测试显式目录优先、旧运行目录回退、开发目录回退及空值；测试不得改变进程全局环境。
- 部署测试验证宿主目录挂载、数据与临时目录环境变量、已有配置保留，不再创建 Docker 命名数据卷。
- 管理进程与子进程日志写入 `runtime/logs`，覆盖日志内容、轮换与进程停止后的资源释放。
- 修改验证后提交推送，等待对应 CI 与 Docker 发布 workflow 成功，再进行现场容器重建。
- 现场保留 `/home/daniel/mskplt/runtime`、管理员配置、更新源和现有 HTTP/gRPC 端口；备份部署脚本后仅重建平台容器，核对健康、版本、日志与数据路径，并验证程序更新。管理器会保留已有安装状态，不能仅用新镜像标签判断实际程序版本。
- 不删除已有版本或业务数据，不更改其他业务容器。
