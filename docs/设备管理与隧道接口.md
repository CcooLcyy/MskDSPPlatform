# 设备管理与隧道接口

管理员登录平台后进入 `/devices`，只填写设备名称即可创建设备；平台自动生成唯一设备 ID 和接入令牌，并为创建时已有的全部上位机账号默认保存模块访问、SSH 两项权限，无需再次点击“保存权限”。创建成功后展示设备名称、设备 ID 和一次性令牌，支持分别复制及一键复制接入配置，供配置人员填入现有下位机接入配置页面；本轮不增加整段配置导入功能。设备出厂前，使用上位机现场直连下位机，将设备 ID、令牌、接入开关及 SSH 设置保存到设备。普通上位机账号没有 Web 管理权限。

默认授权仅在新建设备时生效，设备及授权在同一事务中保存，任一写入失败则整体回滚。旧设备的已有权限（含未授权或手动取消的权限）保持原样；此后新增账号不追溯授权，需要管理员按设备设置。停用账号也保留默认授权，但停用状态仍阻止登录和远程访问；没有账号时可以正常创建设备。单设备最多 1024 个授权账号，超限时创建失败且不留下设备记录。管理员仍可按账号取消任一权限并保存，重新选择设备时显示实际保存值。

验证兼容边界：共享协议子模块中的旧 `scripts/remote_smoke.py` 仍假定新设备初始未授权，需先显式清空该设备授权再验证不可见，或更新为默认可见的预期。本次未修改该子模块；本地 Rust 和页面检查不代表该跨语言脚本通过。

自动生成的设备 ID 使用 `device-` 加随机 UUID 的 32 位小写十六进制字符，与设备名称无关；同名设备各有独立 ID，修改名称、轮换令牌不会改变 ID。现有设备 ID 保持不变。为兼容已有接口调用，API 仍接受显式提供的合法 `device_id`，其规则保持为 1～128 位字母、数字、点、横线或下划线；显式空值和非法值仍拒绝。设备名称支持中文，沿用 1～128 字节且无控制字符的校验。

设备令牌为随机高熵值，数据库只保存 SHA256 摘要；列表与详情不返回令牌。令牌仅创建/轮换响应出现，页面离开或清除显示后无法找回，需要重新轮换。复制操作不持久化令牌；轮换时展示同一设备的 ID 和新令牌。轮换、禁用及删除会关闭现有设备连接和隧道。设备及授权保存在业务数据根目录 `remote/remote.sqlite3`。本轮只调整平台，不修改上位机、下位机或共享协议。

## 管理 API

设备管理弹窗统一使用“保存修改”按钮，一次保存设备名称、启用状态及下方账号权限。页面提交前复核账号列表和角色；设备信息与授权在同一数据库事务中写入，校验或写入失败时整体回滚。管理员角色自动拥有全部权限，页面只提交运维账号的显式授权。具体一致性与验收见 [账号删除与设备统一保存](账号删除与设备统一保存.md)。

所有接口使用现有管理员会话 Cookie。写请求须带 `X-MskDSP-Action: device`，请求来源与 Host 同源；JSON 请求设置 `Content-Type: application/json`，响应为 `Cache-Control: no-store`。

| 方法 | 路径 | 请求/结果 |
| --- | --- | --- |
| GET | `/api/v1/devices` | 设备列表，含在线状态、服务和连接组件版本 |
| POST | `/api/v1/devices` | `{display_name}`；省略 `device_id` 时平台自动生成，保留显式 ID 的兼容调用；201 返回设备（含 `device_id`、`display_name`）及一次性 `token` |
| GET | `/api/v1/devices/{id}` | 设备详情，不含令牌 |
| PUT | `/api/v1/devices/{id}` | `{display_name,enabled,grants?}`；提供 `grants` 时与设备信息同事务完整替换权限，空数组清空显式授权；省略时兼容旧请求，只保存设备信息 |
| DELETE | `/api/v1/devices/{id}` | 删除设备与授权，204 |
| GET | `/api/v1/devices/{id}/grants` | 账号权限数组 |
| PUT | `/api/v1/devices/{id}/grants` | `[{account_id,allow_grpc,allow_ssh},...]` 完整替换，204；最多 1024 个账号 |
| POST | `/api/v1/devices/{id}/token` | 轮换并仅本次返回 `token` |

授权账号必须已存在。模块访问允许设备已开放模块的全部业务操作；平台不解析字节，不能作为只读权限使用。SSH 仍由现场系统账号及 SSH 主机密钥完成端到端认证。

## 下位机出厂配置

平台创建设备和授权不会自动写入现场下位机。上位机必须先直连下位机管理服务，再通过 `GetPlatformAccessConfig` 读取脱敏状态、通过 `SetPlatformAccessConfig` 下发接入开关、设备 ID、只写设备令牌及 SSH 设置。修改携带预期修订；空令牌保留原值，更换已有身份时要提供新令牌或显式清除，不能误用旧凭据。

下位机保存 `./conf/platform_access.json`，使用 0600 权限及同目录原子替换；读取接口只返回 `token_configured`，不返回原始令牌。保存成功后立即应用，重启、断电及升级后自动恢复。旧环境变量不作为用户配置入口；固定平台地址不从文件或环境变量覆盖。现有 ConfigPusher 业务配置下发方式不变。

安装器保留宿主机 conf 与容器 `/opt/mskdsp/conf` 的绑定，版本更新和同版本重建均保留该文件内容及权限。令牌不进入安装器输出、普通配置导出或上位机工作区。

## gRPC 连接

共享协议为 `platform-proto/platform/v1/remote.proto`，平台同一个 gRPC 监听端口提供 `DeviceAccessService` 和 `RemoteAccessService`。设备使用独立 Bearer 令牌，上位机使用现有 AgentService.Login 返回的用户会话。

- 设备先调用 `ConnectDevice`，首帧 Hello；30 秒发送心跳，90 秒无心跳关闭。
- 上位机 `ListDevices` 仅返回获授权设备；`OpenTunnel` 首帧选择设备及逻辑服务，禁止任意地址。
- 平台通知设备后，设备先连接本机目标，再通过 `AttachTunnel` 消费一次性票据。
- 打开全过程最多 15 秒；每设备最多 16 条，平台总共最多 4096 条隧道。帧为 1～65536 字节，方向队列各 8 帧，发送阻塞最多 30 秒。两方向独立转发。
- EOF/half_close 保留反方向尾部；掉线、取消、撤权或登录失效结束会话，不重放字节。授权独立监视周期 1 秒，背压时仍可中断。

平台统一使用明文 gRPC，下位机固定目标为 `60.208.15.90:50000`，出厂配置卡不提供地址、证书或传输模式编辑项。上位机登录该平台时使用 `http://60.208.15.90:50000`，账号和设备认证保持有效；本轮不改变已有登录设置页面。试用示例见 [Ubuntu 配置](远程设备接入与SSH隧道.md#ubuntu-试用配置示例)。内置 `--probe-grpc` 直接使用明文只读 RPC 检查协议，不建立账号会话。

本地测试不代表现场网络、ARM64 或真实 SSH 验收。完整方案及三端边界见 [远程设备接入与 SSH 隧道](远程设备接入与SSH隧道.md)。
