# 设备管理与隧道接口

管理员登录平台后进入 `/devices`，创建设备并保存一次性返回的接入令牌，再给已有上位机账号勾选模块访问、SSH 权限。普通上位机账号没有 Web 管理权限。

设备标识固定为 1～128 位字母、数字、点、横线或下划线。设备令牌为随机高熵值，数据库只保存 SHA256 摘要；列表与详情不返回令牌。令牌仅创建/轮换响应出现，页面离开或清除显示后无法找回，需要重新轮换。轮换、禁用及删除会关闭现有设备连接和隧道。设备及授权保存在业务数据根目录 `remote/remote.sqlite3`。

## 管理 API

所有接口使用现有管理员会话 Cookie。写请求须带 `X-MskDSP-Action: device`，请求来源与 Host 同源；JSON 请求设置 `Content-Type: application/json`，响应为 `Cache-Control: no-store`。

| 方法 | 路径 | 请求/结果 |
| --- | --- | --- |
| GET | `/api/v1/devices` | 设备列表，含在线状态、服务和连接组件版本 |
| POST | `/api/v1/devices` | `{device_id,display_name}`；201 返回设备及一次性 `token` |
| GET | `/api/v1/devices/{id}` | 设备详情，不含令牌 |
| PUT | `/api/v1/devices/{id}` | `{display_name,enabled}` |
| DELETE | `/api/v1/devices/{id}` | 删除设备与授权，204 |
| GET | `/api/v1/devices/{id}/grants` | 账号权限数组 |
| PUT | `/api/v1/devices/{id}/grants` | `[{account_id,allow_grpc,allow_ssh},...]` 完整替换，204；最多 1024 个账号 |
| POST | `/api/v1/devices/{id}/token` | 轮换并仅本次返回 `token` |

授权账号必须已存在。模块访问允许设备已开放模块的全部业务操作；平台不解析字节，不能作为只读权限使用。SSH 仍由现场系统账号及 SSH 主机密钥完成端到端认证。

## gRPC 连接

共享协议为 `platform-proto/platform/v1/remote.proto`，平台同一个 gRPC 监听端口提供 `DeviceAccessService` 和 `RemoteAccessService`。设备使用独立 Bearer 令牌，上位机使用现有 AgentService.Login 返回的用户会话。

- 设备先调用 `ConnectDevice`，首帧 Hello；30 秒发送心跳，90 秒无心跳关闭。
- 上位机 `ListDevices` 仅返回获授权设备；`OpenTunnel` 首帧选择设备及逻辑服务，禁止任意地址。
- 平台通知设备后，设备先连接本机目标，再通过 `AttachTunnel` 消费一次性票据。
- 打开全过程最多 15 秒；每设备最多 16 条，平台总共最多 4096 条隧道。帧为 1～65536 字节，方向队列各 8 帧，发送阻塞最多 30 秒。两方向独立转发。
- EOF/half_close 保留反方向尾部；掉线、取消、撤权或登录失效结束会话，不重放字节。授权独立监视周期 1 秒，背压时仍可中断。

平台统一使用明文 gRPC，不需要证书文件或额外的传输模式开关。上位机填写 `http://主机:端口`，下位机填写 `主机:端口`；账号和设备认证保持有效。试用示例见 [Ubuntu 配置](远程设备接入与SSH隧道.md#ubuntu-试用配置示例)。内置 `--probe-grpc` 直接使用明文只读 RPC 检查协议，不建立账号会话。

本地测试不代表现场网络、ARM64 或真实 SSH 验收。完整方案及三端边界见 [远程设备接入与 SSH 隧道](远程设备接入与SSH隧道.md)。
