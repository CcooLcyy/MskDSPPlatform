# 平台界面组织

## 范围与目标

统一登录、程序更新、点表与回收站页面。使用统一的导航、排版、按钮层级及浅色/深色主题；浏览目录、编辑数据、恢复误删和安装更新各有清楚入口。保留现有 API、管理员认证、版本冲突检查、草稿保护及数据限制，不新增设备管理等尚未实现的入口。

## 页面分工

- 登录：集中呈现管理员账号与密码表单，不预填密码；品牌说明与登录操作分开，明确失败和限流提示。登录后和平台首页默认进入点表工作台。
- 点表工作台：平台导航、点表目录和编辑工作区分层；模板信息与点位字段按用途分组，说明、来源和高级配置按需展开。保存作为主操作，导出/复制为辅助操作，删除单独标识。
- 回收站：明确显示删除时间、到期时间和恢复操作；切换视图保留编辑草稿，恢复失败保留记录。仅显示真实读取的数据，不将未加载的数量显示为零。
- 程序更新：区分当前版本、可用版本与任务状态；检查更新和安装更新分离，不显示更新来源或技术详情。页面读取状态，不自动检查或安装更新。

## 实现约束与验证

共用基础样式放在 `web/platform.css`，通过同源 `/assets/platform.css` 提供。所有动态业务内容使用文本赋值，不引入外部字体、图标脚本或前端框架。系统主题、手动选择和跨页偏好保持一致。

桌面使用侧边导航，窄屏改为横向导航和单列内容。支持键盘焦点、中文字段、错误状态、空列表与请求中状态；重要操作不能因布局变化而变成默认自动动作。

验证登录、更新、点表和回收站交互回归；浏览器检查浅色、深色、窄屏、模板编辑及恢复后的视图。完成后提交推送，等待 CI 成功，通过平台自带更新部署，保留业务容器和数据。

## 编辑效率优化（2026-10-19）

本轮经用户确认优化全部已讨论项目。范围限于网页、对应测试与本设计文档，保留现有 HTTP API、数据格式、认证和更新机制；提交同步不代表已部署，线上更新另行安排。

### 点表工作台

- 模板信息默认以摘要呈现，可展开编辑；目录支持收起与重新展开，点位成为主要工作区。减少页面顶部留白，普通读取成功提示使用轻量状态，错误仍需明显。
- 提供点位表格与详细编辑，在表格中直接比较标签、地址、类型、倍率和单位；点击点位进入详细编辑，保留搜索和当前选择，提供分组与读取/写入筛选。大量点位避免一次生成过量 DOM。
- 保存校验失败时保留全部草稿，定位对应点位并展开相关区域，字段旁显示中文原因、标记无效状态。切换点位和重新校验后清理过期错误，不把服务端错误误标到无关字段。
- 功能码、数据类型和寄存器数量联动提示兼容关系；不得静默丢弃位解析、枚举或条件配置。精度字段仍保存十进制原文。
- 下载明确区分已保存版本与当前草稿，未保存的点表也可导出校验通过的草稿，避免修改后下载旧版本造成误解。草稿使用与大小校验一致的紧凑 JSON 导出，保证不因排版膨胀而超过重新导入的 10 MiB 限制。
- `/modbus-templates#trash` 初次打开和浏览器前进/后退均进入对应视图，切换保留编辑草稿；统一各页点表导航名称。

### 软件版本与平台更新

- 软件历史默认紧凑列表，显示产品、版本、架构、通道、入库时间与操作；详细信息按需展开，并可切换卡片。保留产品和通道筛选，补版本搜索和架构筛选，区分仓库为空与筛选无结果，支持清除筛选。
- 发布与撤回以实际通道引用为依据。无该通道发布时禁用撤回，优先选择已发布通道。发布确认显示原推荐版本与目标版本，并明确 Stable 通道影响；撤回说明仅停止该通道推荐，曾发布文件仍可下载。
- 安装更新前确认当前版本、目标版本与短暂断连影响，并呈现可获得的变更说明；未提供说明时如实标示。取消不发请求，连续点击不重复提交。保留任务状态、自动重连、失败恢复和手动回退行为。

### 验收标准

1. 桌面常用宽度与窄屏均可访问全部操作，浅色/深色无横向页面溢出；点表编辑不依赖固定大屏。
2. 用既有三份真实模板验证表格、筛选、逐点编辑、精度保留、保存/导出和草稿保护；大点表的可见列表数量受限。
3. 回收站深链接、视图切换、草稿保留、恢复失败、登录失效等既有行为通过回归。
4. 故意输入错误地址、重复标签、类型/寄存器不匹配和高级配置错误，能识别对应点位、字段及原因，不发送无效保存请求。
5. 软件筛选无结果可清除；未发布通道不能撤回；发布确认可核对版本切换，取消不提交。
6. 更新安装确认取消不提交，确认只提交一次；服务端缺少变更说明时不显示虚构内容。

### 本轮验证记录

- 本地 Python 全套测试发现 194 项，181 项通过、13 项跳过；跳过项依赖 POSIX/Linux 文件锁或未安装的 grpcio/grpcio-tools。
- `cargo test --locked --offline`：91 项通过。仍有既有的 Agent 会话字段未读取警告。
- 点表页面脚本使用实际三份点表与最小 DOM 验证编辑、分页、字段校验、草稿保护、回收站和导出；补充 10000 点草稿的 Blob 导出及回导边界回归。
- 浏览器在隔离预览服务上使用真实点表样例验证了分页、键盘选点、读写筛选、地址错误定位及修正保存、回收站切换保留选点、跨页回收站深链接与后退。桌面浅色/深色及 390px 窄屏均已检查；窄屏表格使用局部横向滚动，地址和类型保持完整，页面不横向溢出。
- 软件页检查搜索空态及窄屏双列筛选，更新页检查当前/可用版本与任务区。安装确认框曾阻塞内置预览，用户已手动取消；确认取消及防重复提交由页面脚本回归验证，未执行真实安装。浏览器截图保存在工作区外的本次会话可视化目录。
- 本轮未部署平台，未触发真实安装、回退或软件发布。

## 软件管理页内分区（2026-10-20）

用户确认保持单一软件管理入口，在同一页面按软件划分三个独立区块。本轮替代通用产品筛选总表，保留 `/software` 路由、现有软件 API、认证及逐包发布/撤回语义；不新增侧栏子菜单，不合并程序更新页，不改后端和软件仓库数据。

### 页面与交互

- 页面标题及所有既有 `/software` 导航统一为“软件管理”。上位机、下位机、平台软件三个区块固定同时存在，即使某个软件没有安装包也呈现它自己的空态。
- 上下位机区块默认展示各通道推荐版本及对应架构；历史版本默认折叠，展开后显示当前软件的版本列表与操作。不再显示全局产品筛选或重复产品列。
- 搜索、通道及架构筛选位于各自历史区域，互不影响；刷新和发布/撤回后保留其他区块的展开状态与筛选。清除筛选仅作用于当前软件。通道摘要始终反映完整仓库中的真实推荐关系，不随历史筛选改变。
- 平台区块显示可读取的当前运行版本、上次检查结果与候选历史包，提供前往程序更新页的入口。只读获取 `/api/update/status`；接口不可用时局部说明，不影响上下位机列表，不能把上次检查结果当作仓库最新候选包，不能把缺失状态显示为正常或自动检查/安装更新。
- 同一批次不同架构的安装包可归组展示，逐包保留完整版本号、通道及操作。优先使用可信来源信息与 CI 流水线标记，或相同完整版本加一致来源；来源不足、流水线不同、提交/引用不同或同架构重复包不强行合并。不按显示前缀或入库时间猜测批次。分组仅影响展示，不新增批量发布操作。
- 推荐版本只认安装包当前 `channels` 引用；入库元数据的 `channel` 不能当作已发布。上位机切换新版本会撤下该通道旧版本的其他架构，确认应列出影响；下位机按架构独立推荐。分组展示不改变这些服务端语义。
- 搜索无结果与该软件尚无包分别提示；查询失败、会话失效和请求中状态延续现有保护。动态数据使用文本赋值，日期使用浏览器本地时区并保留原始时间提示。
- 页面继续使用共用浅色/深色主题。窄屏下区块纵向排列，筛选紧凑排列，历史表格局部横向滚动，长版本号不撑宽页面。

### 验收标准

1. 首屏能识别三个软件区块，历史默认折叠，无全局产品筛选，无侧栏软件子菜单。
2. 每个软件的搜索、通道、架构和清除筛选均局部生效；切换历史展开、刷新与发布后保留无关区块的操作状态。
3. 已发布通道摘要正确按架构显示版本；筛选历史不能改写通道摘要。无对应发布关系不能撤回，确认、取消、防重复提交、平台包不可公开发布/下载等行为通过回归。
4. 同批多架构包可归组；不同流水线、不同来源与缺失来源包保持独立。展开可见每个包的完整身份和独立操作。
5. 平台状态缺失/失败不阻断其他区块，也不触发检查更新或安装；认证失效仍停止变更。
6. 实际浏览器检查默认三块摘要、历史展开与局部筛选、浅色/深色、390px 窄屏及长版本号。测试与本地预览不等同于线上部署验证。
