# 平台 Docker 三通道发布方案

## 目标与范围

平台基础版本从 `0.0.1` 开始。提供 Linux amd64 Docker 镜像、可通过
`docker load` 导入的压缩镜像包、docker run 部署脚本、版本清单与 SHA256 校验文件。
首轮只发布 CI；Beta、Stable 保留可执行的发布流程，不创建对应分支或正式标签。
本方案不增加设备业务、数据库或 TLS 实现。

## R2 与单容器网页更新

沿用 slaveSim 的当前模式：一个容器内运行常驻 Python 管理进程与 Rust 平台子进程。
管理进程提供更新接口并代理 HTTP，Rust 继续独立提供 gRPC。公开 HTTP 为 8080，
Rust 内部 HTTP 为回环 8081，gRPC 为 50000。页面通过“检查更新”“更新到最新版”
发起更新；加载页面与轮询仅读取状态，不定时检查或安装，不安装宿主机服务。

发布同时上传 R2 的 `mskdsp-platform/{ci,beta,stable}/latest.json`，
各版本含同源的 Docker 镜像包与根成员唯一的 `mskdsp-platform` 二进制包。
资产先上传并公开校验，最后更新入口。项目、通道、平台、版本、完整提交、
大小与 SHA256 均需校验；正式版本不允许不同内容覆盖。旧资产只在入口和保留
对象验证成功后，按当前项目/通道精确清理，不影响其他项目或通道。

更新器只读取只读 `updater.json` 中的固定更新源，网页不接受 URL、命令或文件路径。
候选二进制校验版本身份后才切换；下载阶段旧程序继续服务。切换会短暂停止平台
子进程并断开 gRPC 长连接，客户端需要重连。HTTP 版本、就绪接口和真实 gRPC
握手验证成功后才原子提交状态；失败恢复本地上一版，并报告回滚结果。
配置保持只读挂载，程序版本与安装状态保存在持久化 runtime 卷；重启以最后成功
提交的版本恢复，不能被基础镜像种子覆盖。基础镜像、管理器及系统库升级需单独维护。

默认部署使用 `docker run`，Compose 仅保留可选模板。宿主机端口默认仅回环暴露，
管理页面可通过受保护的网关或 SSH 隧道访问。动作头和 Origin 校验用于限制跨源
浏览器请求，不替代网关管理身份校验。运行端无需 R2 写入凭据或 Docker Socket。

新增验收包括：清单与包异常拒绝、版本倒退/冲突、重复更新互斥、成功提交、失败回滚、
掉电/重启恢复、子进程回收、有界重启，以及页面检查/安装按钮与轮询契约。

## 通道与版本

| 通道 | 自动触发 | 手动触发 | 滚动镜像标签 | GitHub 交付入口 |
| --- | --- | --- | --- | --- |
| CI | 推送 `main` | CI 工作流 | `ci` | `ci-latest` 预发布 |
| Beta | 推送 `beta/X.Y` 或 `beta/X.Y.Z` | 指定 Beta 分支 | `beta` | `beta-latest` 预发布 |
| Stable | 推送 `vX.Y.Z` | 指定已存在的正式标签 | `stable`、`latest` | `vX.Y.Z` 正式发布 |

PR 仅运行检查，不发布。`Cargo.toml` 和 `Cargo.lock` 的自有包版本必须一致。
CI/Beta 使用基础版本加通道、UTC 时间、工作流运行编号和提交短号构成版本；
Docker 标签将 SemVer 中的 `+` 替换成 `-`。Stable 版本必须与正式标签完全一致，
并且提交必须属于至少一个与版本匹配的远端 Beta 分支。

## 构建、验证与发布顺序

1. 校验发布来源，捕获完整提交 SHA；后续步骤使用相同代码，避免分支移动导致版本漂移。
2. 运行发布工具单元测试、Rust 格式检查和已有 Rust 测试。
3. 构建非 root 镜像，在临时容器验证三个 HTTP 接口、版本身份与 gRPC TCP 监听。
4. 生成镜像压缩包、部署配置、清单及校验和，检查 Docker 包内的标签和镜像配置摘要。
5. 发布 R2 程序包、镜像包与清单，再发布 GHCR 镜像及 GitHub Release 资产。
6. CI/Beta 更新滚动入口前确认构建提交仍为对应远端分支的最新提交。

同一通道串行发布。工作流使用仓库自动提供的 `GITHUB_TOKEN`，仅发布作业获得
`contents: write`、`packages: write`，不需要外部镜像库密码。
GHCR 新建包的可见性需在 Packages 设置中核对；公开 Release 离线包可独立使用。

## 验收标准

- `0.0.1` 为唯一基础版本来源；无效版本、错误分支、错误标签、缺少 Beta 来源均被拒绝。
- 首发 CI 成功，产物含镜像包、启动脚本、配置、清单和 SHA256；Beta/Stable 不自动首发。
- 容器监听内部 `0.0.0.0:8080/50000`，部署默认仅映射宿主机 loopback。
- `/api/v1/version` 可核对构建版本、通道、完整提交和构建时间。
- 镜像包可以导入，包内镜像 ID 与清单一致，下载文件校验和与发布记录一致。
- 当前服务缺少原生 TLS 和业务功能；发布通道标识构建来源，不代表新增业务验收。
