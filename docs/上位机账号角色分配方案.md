# 上位机账号角色分配（第一阶段）

## 目标与边界

平台 Web 管理员可以为上位机账号分配管理员（`admin`）或运维人员（`operator`）角色。账号角色是上位机业务身份，不授予平台 Web 管理权限。第一阶段只实现分配、持久化、查询与登录后同步，不改变现有配置、控制、升级及设备授权规则；具体功能权限另行讨论后接入统一鉴权。

## 数据与接口

- 账号新增受校验的 `role` 字段；创建时缺省为 `operator`。旧数据库通过事务迁移，所有已有账号设为 `operator`，保留账号、密码摘要、修订号及有效会话。
- 管理端列表及详情返回角色；创建和更新可选择角色。更新仍检查 `revision`，未传角色时保留原角色以兼容旧客户端。未知角色拒绝，且不产生部分更新。
- 角色分配沿用现有平台 Web 管理员鉴权及操作来源检查，上位机登录令牌不能修改账号或提升自身角色。
- 仅改变角色不递增 `auth_version`，不撤销会话；修改修订号并记录不含密码、令牌的中文审计日志。账号禁用、重置密码继续按原规则撤销会话。
- 平台 `proto/platform/v1/agent.proto` 及上位机镜像 `src-tauri/proto-platform-agent/platform/v1/agent.proto` 的 `AccountIdentity` 增加 `string role = 4`。登录及 `GetSession` 返回数据库当前角色。现有独立平台软件/远程协议仓库没有 Agent 登录协议，本次无需修改其子模块。

## 上位机行为

- 角色只由平台登录响应或已认证的会话查询响应提供，保存在 Rust 会话内存，认证快照向前端返回当前角色；不读取磁盘角色、不增加本地角色选择。
- 登录旧平台时缺失或空角色兼容为 `operator`；非空未知角色视为协议错误，不赋予管理员身份。该兼容不代表后续业务鉴权默认放行。
- 每次既有会话检查成功后同步角色及显示名，角色变化记录中文日志。保持原账号身份检查、代次隔离、过期上限，不通过同步角色延长会话。
- 界面账号入口显示“管理员”或“运维人员”，锁定/退出清除当前身份显示。角色调整无需重新登录或重载工作区草稿。
- 网络暂时断开时保留本次有效会话及最后角色；恢复后同步，到期照常锁定。此阶段不承诺离线即时撤权。

## 验收与异常

先补失败测试，再实现：旧库迁移及重开、创建默认/显式角色、非法角色拒绝、带修订号的角色修改及冲突、缺省更新保留角色、普通身份不能调用管理接口、登录/GetSession 读取最新角色、角色变化不撤销原会话、禁用/密码重置仍撤销、上位机同步升降角色且不续期、旧平台及非法角色兼容、旧响应不能恢复已退出会话。检查平台 Web 角色展示与编辑，以及上位机账号入口。仅执行本地测试、构建及静态检查，不部署平台或连接现场设备。
